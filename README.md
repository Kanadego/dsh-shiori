# dsh-shiori

> 给 DeepSeek Harness 的 agent 一套**分层、会长、也会忘**的长期记忆：人设卡常驻开头，记忆核心每轮注入，原子卡片在你说到它时自己浮上来，长文档式专题按需展开——满了自己下沉，旧了自己淡出。

## 一分钟了解

聊天记录会越滚越长，但模型的上下文不会。你要么把一切都塞进去（然后被截断、被压缩、花光 token），要么就接受它每次醒来都失忆。dsh-shiori 是第三种选择：**把记忆从对话里搬出来，分层存放，按需要取用**。

| 层 | 存什么 | 什么时候进上下文 |
| --- | --- | --- |
| **L0** 人设卡 | 身份、性格、说话方式 | 每轮常驻，摆在对话最前面 |
| **L1** 记忆核心 | 最重要的事实、约定、进行中的事，外加一份专题目录 | 每轮常驻；超预算先压到软目标，硬上限之前绝不截断 |
| **L2** Spark 卡片 | 一条一条的原子记忆：某个梗、某个外号、某个小事实 | 默认不进；你说到相关的话，按触发词自己浮上来 |
| **L3** 专题 | 长文式的沉淀：一个项目的来龙去脉、一份研究笔记 | 只露一行索引；模型觉得需要才去读全文 |

它想解决的三件事：

| 你担心的 | 插件怎么处理 |
| --- | --- |
| 记忆越写越多，最后把上下文撑爆 | 每层各有预算；L1 装满后把细节**下沉**到 L3 专题，只留索引占一行；索引再挤就归档 |
| 存进去就再也想不起来 | L2 卡带触发词，你提到时自动投递；L3 带索引，模型自己会去翻 |
| 越存越乱、该忘的忘不掉 | `organize` 定期把散落的卡片合并成专题，`forgetting` 按半衰期让久不用的条目自己淡出——是真的归档，不是删掉 |

默认装在**只读影子模式**（shadow）：能挂载、能看诊断，但不写盘、不注入、不发请求。要真启用得显式打开 active，并指定两个数据目录。

## 快速开始

### 安装

~~~powershell
dsh plugin --profile web add dsh-shiori
~~~

重启 DSH 后生效。插件以 DSH 原生 bundle 形式挂载（包内声明了 `dsh.bundle.patch`），不需要手改 `cordis.patch.yml`。

> 如果同时装着 `dsh-soul-md`，两者提供 9 个同名工具，宿主的「工具唯一提供者」校验会直接拒绝。先停用其中一个。

### 从源码安装

~~~powershell
npm pack                                              # 得到 dsh-shiori-0.1.0.tgz
dsh plugin --profile web add <你的项目绝对路径>/dsh-shiori-0.1.0.tgz
~~~

### 第一次配置

装上之后是 **inert shadow**：挂载成功，面板显示 `needs-configuration`，但什么都不读写。要到插件详情页「预算」tab 或 profile 的 `cordis.patch.yml` 里补三项：

~~~yaml
- id: shiori
  name: dsh-shiori
  config:
    mode: active
    allowActive: true
    dataRoot: '<你的记忆目录绝对路径>/shiori-data'
    stateRoot: '<你的记忆目录绝对路径>/shiori-state'
~~~

- `dataRoot` 存记忆本身（人设卡、core、专题、卡片库）
- `stateRoot` 存运行账本（幂等记录、投递账、计划、锁）
- 两者必须是**绝对路径**、**互不嵌套**，缺一个就不动

`mode` 不改、只给两个根，就是 shadow 只读：面板能预览模型真实看到的内容（L0 / L1 / 索引），一个字节都不写。适合先看看效果再决定。

### 数据放在哪

数据全部在 `dataRoot` / `stateRoot`，**住在包外面**。升级、重装、卸载都不会碰它们。

## 核心工作机制

一次模型调用，插件做三件事：往开头摆好 L0/L1，扫你新说的话有没有命中 L2 卡，然后把命中的卡片作为一条独立附件塞进上下文。

```
                 ┌─ L0 人设卡 ─┐
每轮注入 ────────┤             ├──→ 系统提示词
                 └─ L1 核心+索引┘

你说了句话 ──→ 触发词匹配 ──→ 0 跳种子（≤3 张）
                              └→ 沿连线/实体扩一跳（≤2 张）
                                    └→ 拼成一条附件消息 → 进上下文

模型想知道某件事 ──→ memory_search / memory_read(topic) ──→ 读到全文
```

<details>
<summary><b>点此展开：几个会反复出现的词</b></summary>

| 词 | 意思 |
| --- | --- |
| **scope** | 一套独立记忆的命名空间。按会话 → 工作区 → 默认人设卡 → `global` 的顺序解析，越具体越优先。换工作区就等于换了一本笔记本 |
| **shadow / active** | shadow 是只读影子：什么都不写；active 才注册工具、写盘、注入。切换要显式加 `allowActive: true`，防止手滑 |
| **inert** | 两个根目录都没给的状态：插件挂载了但什么都不做，只报一条 `needs-configuration` 诊断 |
| **派生索引** | 由 L3 专题自动生成的一行行目录（`- key [scope] — 摘要`），跟 L1 正文一起进上下文。它不属于 core 正文，改写 core 时会自动重算 |
| **下沉** | L1 超过软目标后，把细节搬进 L3 专题、索引里只留一行的动作。原文不会丢 |
| **epoch** | 「这一轮对话的生命期」。记忆被压缩后 epoch +1，L2 的「这张卡已经投过」冷却全部作废，同一张卡在新一轮里可以再浮上来 |
| **operationId** | 所有写工具的幂等键。同一个 id 重试只会得到第一次的结果，不会写两遍 |
| **CAS / revision** | 每次写入都带一个版本记号，改之前先核对，过期的改写会被拒绝而不是覆盖——两个人（或两个会话）同时改同一份记忆时，不会互相吃掉 |

</details>

## 核心功能

### 分层记忆与预算

- **L0 人设卡**：整卡替换，写入超过上限直接拒。它可以是纯文本，也可以按会话 / 工作区分别指定不同的卡。
- **L1 记忆核心**：一段会随对话生长的正文。有软目标（超过就提示该压缩）和硬上限（真超了**绝不截断规则**，而是退回上一次可用的投影；连投影都没有就输出一段英文诊断占位，让你一眼看见出了问题）。
- **L3 专题**：一个主题一个文件，前面有 front-matter（key / 标题 / 摘要 / 更新时间），正文随便写多长。它不占提示词预算，只占索引一行。
- **编排权在模型手里**：什么时候追加、什么时候下沉、下沉到哪个专题，都由模型在工具调用里自己决定——插件只负责守住预算和一致性。

### Spark 闪回

- 卡片存的是**一条一条的原子记忆**：一句话、一个外号、一个约定。每张带 `triggers`（能唤醒它的原话）。
- 匹配是**字面匹配**，不做语义联想：NFC 归一化、英文大小写折叠；纯英文单词按词边界（`cat` 不会命中 `concatenate`），中文按子串。
- 命中的卡片连同它的一跳关联（沿显式连线、共同实体）拼成一条附件消息，标注来源是记忆插件，不打断正在进行的对话。
- **防刷屏**：同一会话同一 epoch 内，同一张卡只投一次；记忆被压缩后 epoch 加一，旧冷却自动失效。
- 卡片带生命期：`vitality: evergreen` 永不衰减，`ephemeral` 按半衰期慢慢淡。你或模型明确说「用了」会续命。

### 整理与遗忘

- **organize（整理）**：分析出三类候选——同一实体下堆积的卡片（cluster，够 8 张才提）、孤立无连线的卡片（isolated）、该连还没连的两张卡（link）。候选先给你看，确认后才生成不可变计划，执行前还要 diff 预览和一次显式确认。
- **forgetting（遗忘）**：分数 `2^(-闲置天数 / 半衰期)`，半衰期随使用次数从 30 天最长涨到 240 天。归档要四个条件全满足：是 active、是 ephemeral、没被别的卡替代、闲置 ≥ 61 天且分数低于阈值。**归档不是删除**，卡片还在库里，Cold 检索照样能查到。

### 原生 web 面板

入口：插件管理器 → dsh-shiori 详情页。六个 tab，操作全在界面上：

| tab | 用来干什么 |
| --- | --- |
| **状态** | 五行中文摘要（运行模式 / 当前作用域 / 服务是否起来 / 人设卡与记忆核心占用）+ 能力标记；原始字段收在「技术细节」里 |
| **记忆 L0/L1** | 看模型真实看到的内容，两层都能就地编辑保存（保存带版本校验） |
| **图谱** | Spark 卡片的节点与连线，拖拽平移、滚轮缩放、点开卡片改内容或加/减连线 |
| **候选 / 计划** | 跑整理分析、审阅候选、预览 diff、确认执行；合并记忆的主战场 |
| **L3 主题** | 主题列表默认只露 key / 标题 / 字数，展开读正文、整篇编辑保存 |
| **预算** | 十个中文字段，带参数名与上限提示；改完要重启生效 |

所有 tab 共用顶部的**工作区 → 会话**两级选择：先选工作区，再选那个工作区下的会话。面板看的就是你选中的那个会话的记忆。

### 幂等写入

所有写工具都收 `operationId`。网络抖动、宿主重试、模型重复调用同一个操作时，只会生效一次——重复的那次拿到的是第一次的结果。跨多个目录的写入走日志式事务，中途崩了下次启动会接着做完或整笔作废，不会留下半个状态。

## 常见问题

| 症状 | 原因与解法 |
| --- | --- |
| 面板显示「shadow 模式，数据界面停用」 | 配置还是 shadow 或 inert。补 `mode: active` + `allowActive: true` + 两个绝对根，重启 |
| 面板整块空白 | 前端渲染出错，打开浏览器控制台（F12）看报错 |
| 会话下拉变成手填框 | 会话列表瞬时取不到，点「刷新」（内置自动重试）；还不行就整页刷新 |
| `REVISION_CONFLICT` | 这份记忆被别处改过了。重新读一次拿新版本号再写，别硬改 |
| `LOCK_BUSY` | 同一个数据目录被两个宿主进程同时写（比如 web 和桌面版都开着）。只留一个 |
| 明明提到了卡却没投递 | L2 关了；触发词跟你的说法对不上；这张卡在本轮已经投过；或者它被判定成泛化标签不扩散。查 `stateRoot/l2/` 里的账 |
| 预算改了没效果 | 预算是**热提交、重启生效**——面板保存的是启动快照，重启后才是新值 |
| `UNSUPPORTED … disabled` | 对应的 `l2` / `organize` / `forgetting` 开关没开 |
| `legacy topics remain read-only` | 这个专题是旧版本写入的，服务端拒绝改写。新建一个专题再合并 |
| 工具报 `tool ownership conflict` | 和 `dsh-soul-md`（或别的记忆插件）撞了同名工具，停用其中一个 |
| 记忆核心变成一段英文诊断 | L1 超过硬上限且没有可用投影。抬高 `budgets.core`，或把细节下沉到专题 |

## 模型侧工具

十六个工具，模型自己调用，不需要你记：

| 工具 | 作用 |
| --- | --- |
| `soul_read` / `soul_update` | 读 / 整卡替换人设卡（CAS） |
| `memory_read` | 无参=当前 L1 渲染；带 topic=该专题全文 |
| `memory_search` | 专题词法检索，只回 key / 标题 / 摘要（可查归档） |
| `memory_append` / `memory_rewrite` | 往 core 或专题追加带日期的片段 / 整段替换 |
| `core_write` | 只替换磁盘上的 core 正文（不含派生索引） |
| `memory_list_topics` / `topic_create` / `topic_append` | 列专题、建专题、往专题追加 |
| `spark_save` / `spark_read` / `spark_update` | 存卡、读卡、改卡（含连线） |
| `spark_forget` / `spark_feedback` / `spark_graph` | 归档或标记被替代 / 标记「用了」续命 / 读图谱 |

## 数据与安全

### 存什么

```
<dataRoot>/
  persona/<scope>.md              人设卡
  scopes/<scope>/core.md          记忆核心正文
  scopes/<scope>/topics/<key>.md  专题（front-matter + 正文）
  sparks/scopes/<scope>/sparks.json  卡片库
  journal/  staging/              跨目录写入的事务日志与暂存
<stateRoot>/
  tool-ops/    工具幂等账
  l2/          L2 投递账（扫描 / 待确认 / 已确认 / 已投递 / 冷却）
  plans/       整理与遗忘的计划（不可变）
  queues/      候选队列快照
  projections/ 上一次可用的 L1 等投影
  completion-* 压缩探针与单写者锁
```

全部是**明文、可直接读**的 Markdown 与 JSON。没有数据库、没有二进制封装——坏了能手工看，也能拿脚本批量处理。

### 安全边界

- **默认什么都不做**：不配置就是 inert shadow，一个字节都不写。要写盘必须同时出现 `mode: active` 和 `allowActive: true`。
- **路径硬校验**：两个根必须绝对、互不嵌套，盘符根单独保护；越界的路径直接拒。
- **不静默覆盖**：所有改写都带版本校验，过期就报 `REVISION_CONFLICT` 让你重读，而不是把别人的改动盖掉。
- **不擅自删数据**：遗忘是**归档**，物理删除不在这套工具里；卸载只移除包，`dataRoot` / `stateRoot` 原样留着。
- **不改别人的提示词**：宿主如果有 `complete: true` 的 section 在前面，本插件的 L0/L1 会被宿主回填覆盖。插件探测到就干脆零注册，并在诊断里写 `completeShadowed`——如实报告，不假装自己在生效。

## 卸载

~~~powershell
dsh plugin --profile web remove dsh-shiori
~~~

只移除包与挂载，**记忆数据一个字节都不动**。想彻底清干净就自己删 `dataRoot` / `stateRoot` 两个目录——插件不会替你做这件事。
