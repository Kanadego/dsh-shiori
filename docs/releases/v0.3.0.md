# v0.3.0

本版本把 0.2.2 / 0.2.3 / 0.2.4 与 0.3.0 的变更合并为一次发布——前三版已先后合入主干但从未单独发版。主线有三条：专题可以归档、图谱整体改版、core 写入收敛为一条路径；另有一轮只读审计发现的修复。

### 新增功能

- **专题归档**：front-matter 记录 `archivedAt`；L1 索引跳过已归档专题，末尾改留一句「另有 N 篇冷专题，memory_search 可查」
- 已归档专题用 `memory_read` 仍可直接读全文；`memory_search` 冷搜只回摘要，不带正文
- **归档入口**：整理页新增 archive-topic 归档计划族，专题行未归档的给「移出索引」，已归档的给徽章与「恢复到索引」；排序把未归档的排在前
- **图谱改版**：改为力导向布局，节点半径按重要度映射，hover 高亮关联节点，搜索可定位到卡片，同一实体的卡片聚在一起
- **专题页改版**：支持关键词搜索与多种排序，显示更新时间，已归档专题带徽章、正文置灰
- **预览卡按计划类型分流**：标题、正文、确认按钮的文案统一按计划类型渲染
- **图谱标签不再被裁**：靠近画布边缘的节点，标签会被拉回画布内，四角的卡片也能看到完整标签

### 改进

- core 写入裁撤 thin-core 整条路径，只剩 `core_write` 一条路，写入行为不再分叉
- 「整理与遗忘」页收敛为只做遗忘
- 最近变更每页条数从 100 改为 20
- 记忆核心上限在两个页面上统一按硬顶执行
- 图谱节点标签自动去重叠，不再相互压盖
- 面板术语按术语表统一改名，文档同步更新

### 修复

- 切换会话时客户端的三处竞态：旧会话的响应晚到不再覆盖新会话的内容，详情页保存只认当前打开的会话
- 整理分析不再误作废刚生成的归档计划
- 归档草案的拒绝文案与实际接受集一致；计划区同一入口的两处文案统一
- 草案 sources 超过 64 时自查拒绝，与执行器同口径
- 手动连线关系名留空时按 related 落库
- 连线关系名校验的报错改成人话
- sparks 存储清理 thin-core 残留

### 注意

- 无 front-matter 的 legacy 裸 md 专题不再降级只读，直接报错——新建专题再合并旧内容
