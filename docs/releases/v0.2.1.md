本版是一个小版本：围绕「候选 / 计划」页重做成**整理与遗忘**页，配套服务端
DTO 与结构化错误调整。记忆数据格式与 wire 方法集（10 个）不变。

## 改动一览

> 以下描述为改版**最终形态**；本版合入之前，请以 `docs/plugin/client.md`
> 「整理与遗忘」章节的「现状（0.2.0）」小节为准。

### 1. 服务端：候选 DTO 与结构化错误

- 候选 / 计划相关的返回 DTO 调整，补齐整理与遗忘页分组、筛选、状态可见性
  所需的字段（候选状态、分组用 kind 等以 `docs/plugin/client.md`
  「整理与遗忘」章节为准）。
- 错误统一为**结构化错误**：`RemoteError.details` 恒为对象（沿用第 6 轮
  details 契约），业务错误带可读的中文口径文案与 `code`，客户端据此把错误
  翻成人话，不再出现 `connection: invalid server-response failure` 之类的
  传输层裸文案。

### 2. 客户端：「整理与遗忘」页重构

「候选 / 计划」tab 重构为「整理与遗忘」（tab 名随本次改版落地，对应
GLOSSARY U0 定稿的目标名）：

- 待处理候选按 **集群 / 可建链接 / 孤立卡** 三类分组折叠，组头带数量
- 新增状态筛选（待处理 / 已阅 / 已忽略）与关键词搜索
- 「标记已阅」改名 **「稍后再说」**：只是收起这条候选，**不删除任何记忆**
- 可建链接与集群候选行点行内「预览整理计划」在**该行下方就地预览**，移除页面级全局
  proposal JSON 文本框；孤立卡没有可连的第二张卡，**不提供预览入口**，只能「稍后再说」
  或「忽略」
- 错误提示翻成人话：中文场景文案 + 下一步动作指引，原始 code 收进
  「技术细节」折叠区
- 计划执行后移除对应候选，修复重复连线报 `REVISION_CONFLICT`：执行成功后该候选
  从队列移除、`queueRevision` 前进，想再对同一对卡连一次需点「分析整理候选」重新分析
  （「刷新」按钮只重新读取队列快照，不会重新分析）；`REVISION_CONFLICT` 等错误提示
  改为指向「分析整理候选」

操作路径与三种状态（待处理 / 已阅 / 已忽略）的可见性细则见
`docs/plugin/client.md`「整理与遗忘」章节。

**人话渲染**（口径与 `docs/plugin/client.md`「整理与遗忘」章节一致）：

- **候选行理由行**：候选行下方单独一行「理由：」小字——可建链接写「两张卡
  都提到实体「a」；都带触发词「b」」（两组只列非空的，都空写「两张卡有
  共同关键词」，数据来自 `evidence.sharedEntities` / `sharedTriggers`）；
  集群写「N 张卡都共享实体/触发词「term」，可以合并成一个主题」（
  `evidence.sharedTerm` + `field`）；孤立卡写「这张卡没有和任何卡相连」，
  有旧连线时追加「（另有 N 条指向已退休卡的旧连线）」（
  `evidence.ignoredRetiredTargets`）。evidence 缺失或形状不对就不显示，
  不编理由。
- **预览卡人话文案**：PlanView 预览卡改为「标题 + 2–3 行正文」——标题按
  计划 kind 显示「连起来」/「合并进主题」/「core 瘦身」（未知 kind 原样）；
  link 正文说明把哪张卡连到哪张卡、关系与「连错了到卡片详情删连线即可」；
  merge-topic 正文说明合并进哪个主题与「合并后源卡会退休，这一步不可
  撤销」；thin-core 正文只报「core 正文 X → Y 字」。planId / planDigest /
  summary 与**整个原始 diff** 收进默认折叠的「原始信息」。
- **确认按钮文案对照**：link 用主按钮「就这么连起来」（可撤销，到卡片详情
  删连线）；merge-topic 用 danger 红「确认合并（不可撤销）」；thin-core 有
  danger 红「确认瘦身」按钮，但点下去服务端一律拒 `UNSUPPORTED`（仅草案、
  执行器一律拒绝）；未知 kind 兜底「确认执行」。

## 本次明确不做

以下事项**不在本版范围**，后续版本另行安排：

- **F6 自动触发**：候选的自动分析 / 定时整理触发。本版整理与遗忘页仍是
  手动发起（点「分析整理候选」/「分析遗忘候选」），不做后台定时自动跑。
- **心跳联动**：与心跳插件（dsh-heartbeat）的联动。本版不做：整理与遗忘页
  不读取、不响应心跳状态，候选分析 / 整理 / 遗忘动作均由用户在页面上手动
  发起，不由心跳事件驱动。
