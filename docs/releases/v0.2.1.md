本版是一个小版本：围绕「候选 / 计划」页重做成**整理与遗忘**页，配套服务端
DTO 与结构化错误调整。记忆数据格式与 wire 方法集（10 个）不变。

## 改动一览

> 以下描述为改版**最终形态**；本版合入之前，请以 `docs/plugin/client.md`
> 「整理与遗忘」章节的「现状（0.2.0）」小节为准。

### 1. 服务端：候选 DTO 与结构化错误

- 候选 / 计划相关的返回 DTO 调整，补齐整理与遗忘页分组、筛选、状态可见性
  所需的字段（候选状态、分组用 kind 等以 `docs/plugin/client.md`
  「整理与遗忘」章节为准）。
- 错误统一为**结构化错误**：`RemoteError.details` 恒为对象（沿用第 6 轮
  details 契约），业务错误带可读的中文口径文案与 `code`，客户端据此把错误
  翻成人话，不再出现 `connection: invalid server-response failure` 之类的
  传输层裸文案。

### 2. 客户端：「整理与遗忘」页重构

「候选 / 计划」tab 重构为「整理与遗忘」（tab 名随本次改版落地，对应
GLOSSARY U0 定稿的目标名）：

- 待处理候选按 **集群 / 可建链接 / 孤立卡** 三类分组折叠，组头带数量
- 新增状态筛选（待处理 / 已阅 / 已忽略）与关键词搜索
- 「标记已阅」改名 **「稍后再说」**：只是收起这条候选，**不删除任何记忆**
- 点行内「预览整理计划」在**该行下方就地预览**，移除页面级全局 proposal JSON 文本框
- 错误提示翻成人话：中文场景文案 + 下一步动作指引，原始 code 收进
  「技术细节」折叠区

操作路径与三种状态（待处理 / 已阅 / 已忽略）的可见性细则见
`docs/plugin/client.md`「整理与遗忘」章节。

### 3. 文档

## 本次明确不做

以下事项**不在本版范围**，后续版本另行安排：

- **F6 自动触发**：候选的自动分析 / 定时整理触发。本版整理与遗忘页仍是
  手动发起（点「分析整理候选」/「分析遗忘候选」），不做后台定时自动跑。
- **心跳联动**：与心跳插件（dsh-heartbeat）的联动。本版不做：整理与遗忘页
  不读取、不响应心跳状态，候选分析 / 整理 / 遗忘动作均由用户在页面上手动
  发起，不由心跳事件驱动。

## 兼容与限制（待发版时确认）

- wire 方法集不变：仍为 10 个 wire 方法（`src/plugin/client-rpc.mjs` 的
  `CONTRACT_METHODS`：getStatus / getMemoryView / getGraph / executeTool /
  listCandidates / analyze / reviewCandidate / previewPlan / executePlan /
  getTimeline）。注意其中 `getStatus` 是纯内存投影，不进在途排空——在途排空
  的 `DRAINED_MANAGEMENT_METHODS` 是其余 9 个
- 记忆数据格式不变，升级无数据迁移
- 依赖区间与测试结果发版前补记
