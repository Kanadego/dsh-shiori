# dsh-shiori v0.2.1

**「整理与遗忘」页重做：候选分组折叠、筛选搜索、就地预览、错误说人话，顺手修掉三处会把人卡住的坑。**

0.2.0 让记忆能想起来了；这一版收拾的是**用起来**。整理页以前把二十多条候选平铺一屏、原始 JSON 直接怼在脸上，还挂一个「标记已阅」让人猜是收藏还是看完。现在它知道哪些能动手、哪些该收起来，也肯把话说清楚了。

## 候选按类型分组，默认只展开能动手的

待处理候选分三类，组头带数量：

- **集群**——多张卡共享同一实体或触发词，可以合并成一个主题
- **可建链接**——两张卡该连还没连
- **孤立卡**——没有任何连线，默认收起

孤立卡放在最前面占屏没意义，它没有可执行的动作，先折叠起来。

## 筛选与搜索

状态 chip 切「全部 / 待处理 / 已阅 / 已忽略」，再配一个关键词搜索框，四十条候选也不用一条条翻。

## 每行写清「为什么建议这么整理」

候选行下方单独一行小字，直接说理由：

- 可建链接：「两张卡都提到实体「npm」」
- 集群：「N 张卡都共享实体 / 触发词「X」，可以合并成一个主题」
- 孤立卡：「这张卡没有和任何卡相连」

理由来自候选自己的证据字段，取不到就不显示——不编。

## 就地预览

点「预览整理计划」，预览卡渲染在**那一行正下方**，不再跳到页面底部去。

原先页面底部那个全局 proposal 文本框已经拿掉了。它是个单一输入框，点第二条候选时会拿第一条的骨架去发请求，于是必然报错——「点第二条就 INVALID_INPUT」的根源就是它。需要手写 proposal 的话，入口收在默认折叠的「高级」区里。

孤立卡不再有预览按钮：它没有第二张卡可连，按钮本来点了只会换来一条校验错误。

## 预览卡说人话

标题加两三行正文，按类型分开写：连哪两张、关系是什么、连错了到卡片详情删掉就行；合并进哪个主题、合并后源卡会退休且不可撤销。确认按钮也跟着换文案——「就这么连起来」「确认合并（不可撤销）」「确认瘦身」。

整份原始 diff 和 planId 都还在，收在「原始信息」折叠区里。

## 错误提示翻成人话

中文场景描述加下一步该做什么，原始的 code 和堆栈收进「技术细节」。不会再迎面甩一句 `connection: invalid server-response failure`。

## 过期候选提前标出来

在面板之外手动改过卡片（连线、断线、改内容），队列里引用它的候选就过期了。以前是点了才报冲突，现在：

- 那一行显示「卡片已改」徽章，说清是哪张卡变了
- 「预览整理计划」和「合并进主题」按钮置灰——两者走同一条版本校验，一并挡掉
- 页顶出现提示条和「重新分析」按钮
- 「稍后再说」「忽略」照常可用

## 执行完的候选会退场

连完一条线，那条候选不再赖在队列里等着下一次冲突。想对同一对卡再连一次，点「分析整理候选」重新跑一遍分析。

顺带说清楚：面板上那个「刷新」只是重新读一次队列快照，不会重新分析。这话现在写在按钮提示里了。

## 「标记已阅」改名「稍后再说」

原名让人分不清是收藏还是看完。它其实只是把候选收起来，**一张记忆都不会删**。

## 修掉的问题

- 点第二条候选必报 INVALID_INPUT——全局单一文本框把候选串了
- 孤立卡的「预览整理计划」必然报错——骨架取不到第二张源卡，退化成占位符被服务端拒掉
- 连线执行后队列不收敛，同一对卡二次连线必报 REVISION_CONFLICT
- 服务端将来新增的候选类型会被静默丢弃，不进任何分组；现在统一收进「其他」组并保留原文
- REVISION_CONFLICT 的提示原来叫你去点「刷新」，但刷新救不回来，改指「分析整理候选」

## 升级提示

- 直接升级，记忆数据格式没变，不用迁移
- 「已阅」「已忽略」目前没有撤销入口
- 整理和结网会真写 `sparks.json`，头一回用之前建议先备份一次 `dataRoot`
