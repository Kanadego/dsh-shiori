# dsh-shiori 面板术语表（U0 定稿）

> 定稿日期：2026-11-01（0.2 迭代 U0）。全文以**中文名为主、层号为辅**；
> `rev` / `queueRevision` / 完整 DTO 等技术细节一律收进各页「技术细节」折叠区，
> 不再出现在页面主位。
>
> 本期（U0–U2）只落地：本表、预算页层号纠错、预算页内文案。**tab 栏名称本期不改**
> （tab 改名随 U3–U8 各页改版落地，见文末对照表的目标名列）。

## 一、四层记忆

| 层级 | 界面名 | 技术名 | 一句话说明 | 出现在哪些页 |
| --- | --- | --- | --- | --- |
| L0 | 人设卡 | persona（`persona.maxChars`） | 用户写给模型的人设与约定，正文整体注入每次对话 | 状态、记忆内容、记忆预算 |
| L1 | 记忆核心 | core（`core.*`） | 模型长期维护的记忆正文，超软水位提示压缩、超硬水位禁止增长 | 状态、记忆内容、记忆预算 |
| L2 | 闪回卡片 | spark（`spark.*`） | 小张的独立记忆卡，按触发词召回后作为附件投递 | 闪回图谱、整理与遗忘、记忆预算 |
| L3 | 专题 | topic（`memory_*` 工具族） | 一篇一篇的主题文档，不占提示词预算，模型按需 `memory_read` 取全文 | 专题 |

> **层号纠错（U0）**：记忆核心是 **L1**，人设卡是 **L0**。v0.1.0 预算页曾把
> core 四个字段标成「L0」（与状态页「人设卡占用（L0）/ 记忆核心占用（L1）」自相
> 矛盾），0.2 起以状态页写法为准，全面板统一。

## 二、界面名 → 技术名对照（页面内文案照此执行）

| 界面名（主位） | 技术名（收进 tooltip / 技术细节） | 后果式说明（机制说明的写法） |
| --- | --- | --- |
| 软水位 | `softChars`（旧 `softRatio`） | 超过这个长度，新增内容开始被压缩着写 |
| 硬水位（硬闸） | `hardChars`（旧 `hardRatio`） | 越过这道闸就不再接受新增内容，只能删减 |
| 硬顶 | `hardCapChars` | 无论如何不能越过的总长度上限 |
| 记忆目标长度（面板不显示） | `targetChars` | 仅用于区间校验、不参与水位（D3 定案）；面板保存时自动收敛进「软水位 ~ 硬水位-1」并写回，用户不需要也不应该手改 |
| 一次投递的附件长度 | `spark.maxChars` | 单次投递的闪回卡片文本总长度上限 |
| 召回种子数 | `spark.seedCount` | 每轮最多召回多少条种子素材 |
| 关联链接数 | `spark.linkCount` | 每轮最多附带多少条 1 跳关联 |

## 四、其他页面名词

| 界面名 | 技术名 | 说明 |
| --- | --- | --- |
| 记忆作用域 | scope / scopeId | 记忆数据属于哪个人设的隔离边界 |
| 整理 | organize | 织网（补链接）、升华（碎片合并成专题）等后台整理动作 |
| 遗忘 | forgetting | 按半衰期给卡片降权、归档的双轨机制 |
| 候选 | candidate | 整理分析产出的待确认动作 |
| 计划 | plan | 候选确认后生成的可预览、可执行的变更集 |
| 整理与遗忘 | 「候选 / 计划」tab 的改版目标名（U0 定稿、U5 落地） | 按 **集群 / 可建链接 / 孤立卡** 三类分组折叠查看整理候选与遗忘计划、加筛选与搜索、点行就地预览的页面；详见 `docs/plugin/client.md` 的「整理与遗忘」章节 |
| 稍后再说（已阅） | reviewed（`reviewCandidate` 的 decision 值） | 把某条候选从「待处理」视图收起，含义是"这条先不看"。**只是收起，不删除任何记忆**：人设卡、记忆核心、闪回卡片、专题一概不动；被收起的候选不消失，可通过状态筛选（已阅）找回。按钮原名「标记已阅」，改版后界面统一叫「稍后再说」，协议值仍发 `reviewed` |
