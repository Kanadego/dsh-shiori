## S1 首次安装可用性（P0）

### 现状
新用户装完插件，面板只有一行黄字「需要先完成配置，记忆才能工作（needs-configuration）」，其余全空。根因是三个默认值叠加：

- `src/plugin/config.mjs:171` — `mode` 默认 `shadow`
- `src/plugin/config.mjs:173` — `dataRoot` 默认 `null`
- `src/plugin/config.mjs:174` — `stateRoot` 默认 `null`
- `src/plugin/config.mjs:18` — 仅当两个 root 皆 null 且 mode=shadow 才允许 inert 挂载
- `src/plugin/controller.mjs:1311` — inert 态「不启 runtime、不注册任何宿主资源」
- `client/index.js:1116` — 前端只提示，不给修复入口

### 目标
装完即可见、可点、可启用，不需要用户翻配置文件。

### 改动
1. **根路径默认化**：`normalizePluginConfig` 在两 root 为 null 时填入
   `<DSH_HOME>/shiori-data` 与 `<DSH_HOME>/shiori-state`，并在 apply 阶段 `mkdir -p`。
   - 解析写法照官方惯例：`process.env.DSH_HOME || path.join(os.homedir(), '.dsh')`
     （参照 `dsh-experimental-liveshare/lib/index.js:7748` 的 `defaultOwnerStateFile`）。
   - `DSH_HOME` 缺省 `~/.dsh`；Windows 上即 `C:\Users\<user>\.dsh\`，与现有部署路径一致，存量数据零迁移。
   - 落点写进 config 的 description，让用户知道默认在哪。
2. **启用按钮**：面板顶部在 shadow 态显示「启用记忆」按钮 → 一次性写入
   `mode: active` + `allowActive: true` + `defaultPersona`（默认空卡名）。
   走现有 settings 写接口，不新增 RPC 方法。
3. **初始化卡片**：needs-configuration 态不再只挂一行黄字，改挂一张卡片：
   - 说明缺什么（三行：根路径 / 模式 / 人设卡）
   - 「初始化」按钮：建空 core.md、建一张空人设卡、建组清单默认模板（依赖 S3）
4. **不静默写盘**：mode 仍默认 shadow，只有用户点「启用」才切 active。符合现有安全取向。

### 验收
- 全新 profile 装包 → 打开面板 → 三行状态都显示具体路径，无 needs-configuration
- 点「启用」→ 刷新后 `status.mode === 'active'`，工具列表出现 21 个记忆工具
- data 目录与 state 目录在默认位置被创建，权限正常

## S2 侧边栏独立入口（P0）

### 现状
面板注册在 `plugins.bundle.config` 槽位（插件管理器 → 详情页），必须滚过 README 才能到。
详情页顺序由 DSH 固定（插件头 → README → 插件面板），`dsh-plugin-detail/lib/types/document.js:97` 只返回 readme 一种文档，无 order 字段，插件侧无法调序。

### 目标
侧边栏出现 shiori 图标，点开直达面板全屏视图；详情页入口保留。

### 改动
在 `client/index.js` 的 `apply` 里补两个槽位（模板见 `dsh-email/lib/client.js:136-141`）：

```js
ctx.slots.inject('main', () => ctx.slots.register(
  { name: 'main', key: 'shiori', inject: () => ({ ...inject?.(), workbench: true }) },
  PanelView));
ctx.slots.inject('sidebar.panellist', () => ctx.slots.register(
  { name: 'sidebar.panellist', id: 'shiori', order: 60, label: '记忆' },
  function ShioriIcon({ size }) { return h(Icon, { name: 'shiori', size }); }));
```

- 面板组件复用现有 `PanelView`，但把宽度/滚动从「详情页卡片」改成「全屏容器」：外层加 scope class，样式里补 `max-width` 与 `padding` 覆盖。
- 图标沿用包内 `icon.png`（橙），与插件管理列表保持一致。

### 验收
- 侧边栏出现「记忆」图标，点击直接进面板，无需经过 README
- 详情页入口仍可用（不回归）
- 面板在 1440 宽与 900 宽下都不横向溢出

## S3 分组索引 group（P1）

### 定位
**本期只做数据层 + 管理 UI，L1 索引保持平铺不折叠。** 折叠读法（钉住 + 组摘要）留待 0.5，等组规模真实起来再定参数。

### 3.1 数据契约
topic front-matter 新增两个可选字段：

```yaml
group: ["dev", "self"]   # 首个是主组（计数/摘要），其余为兼属；软上限 3，超了给提示
pinned: false            # 本期不参与渲染，只落数据，供 0.5 使用
```

- 缺省视为 `group: []`（未分组），**不改写现有文件的 front-matter**，读取时补默认值。
- 一个 topic 可挂多组；写操作只允许主组决定归属计数。
- 校验：group 必须是已存在的组 key（不存在则报错并提示先建组）。

### 3.2 组清单文件
`<dataRoot>/scopes/<scopeId>/groups.json`（scope 内私有，不跨人设共享）：

```json
{ "version": 1, "groups": [{ "key": "dev", "title": "开发与配置", "summary": "DSH / 插件 / 发版 / 沙箱", "order": 10 }] }
```

- 随包带一版默认模板（开发与配置 / 自我与关系 / 项目与工具 / 生活与偏好），首次初始化时写入。
- 原子写 + 与 topic 写入同一把锁；删除组前必须把组内 topic 迁出，否则拒绝。

### 3.3 工具
新增 `group_manage`（agent 可调）：

| action | 参数 | 行为 |
|---|---|---|
| list | — | 返回组 key/title/summary/order 与各组 topic 数 |
| create | key,title,summary,order | 建组，key 冲突报错 |
| update | key,title?,summary?,order? | 改元信息 |
| delete | key,migrateTo? | 组空则删；非空必须给 migrateTo |

topic 侧的 `topic_create` / `topic_append` 增加可选 `group` 参数。

### 3.4 管理 UI
挂在「遗忘 → 专题索引导航」卡片下方，独立一块「分组管理」：
- 组列表（key / 标题 / 摘要 / topic 数 / 排序）
- 建组、改名、改摘要、调序、删除（带迁移确认）
- 组内 topic 的增删改与平铺列表**用同一套组件**，不做第二套交互

### 3.5 迁移与测试
- 现有 26 个 topic：**平铺不动**，读取时补 `group: []`。
- 测试在 prefill（`test/**/fixtures`）里建 3 个组 + 8 个 topic 的夹具，覆盖：多组挂载、删组拒绝、迁移、group 不存在报错。

### 验收
- agent 能通过 `group_manage` 建组并把 topic 归进去，`memory_read` 与 `memory_list_topics` 都反映 group
- 删非空组被拒绝，给 migrateTo 后迁移成功
- 现有数据零改动，L1 渲染与 0.3.1 完全一致

## S5 模型下载与目录（P1）

### 目录
`<dataRoot>/models/`（跟 data 走，升级插件不重下）。`semantic.cacheDir` 默认值从 `""` 改为该路径。

### 下载流程
1. 状态页「建立向量」旁增加「下载模型」按钮；未装模型时按钮高亮。
2. 点击 → 后台任务（非阻塞）+ 进度条（状态页显示百分比与已下载字节）。
3. 源顺序：`https://hf-mirror.com/` → `https://huggingface.co/` → 失败。
4. 全失败 → 报错卡片：说明网络原因、给「手动指定模型目录」输入框、给一段可一键复制的安装提示词（提示词内含规范目录写法，用户可贴给别的 agent 代装）。
5. 下完自动校验维度（512）与文件名，校验通过才允许建索引。

### 实现要点
- 现有加载走 `src/semantic/local.mjs:114` `pipeline("feature-extraction", model, { dtype })`。
- 进度用 transformers.js 自带回调，不自己写下载器：`pipeline(task, model, { progress_callback })`，
  回调收到 `{ status, name, file, progress, loaded, total }`，status 五态
  `initiate | download | progress | done | ready`（字段定义见 `@huggingface/transformers/src/utils/core.js:20-46`）。
- 一条 pipeline 会拉多个文件（config / tokenizer / onnx），进度要**按 total 字节加权聚合**并按 file 去重，
  否则进度条会来回跳。
- env 三处：`env.cacheDir = <dataRoot>/models`、`env.remoteHost = 'https://hf-mirror.com/'`（失败回落 huggingface.co）。
- 后台任务需要可取消（关闭面板不中断，但可手动取消）。

### 验收
- 干净机器点一次按钮，模型落到 `<dataRoot>/models` 并自动建索引成功
- 断网时给出可读错误与手动路径，不白屏
- 升级插件（重装包）后模型仍在，无需重下

## S6 卸载与焚毁（P2）

### 目标
一条命令/一个按钮完成「卸载插件 + 删除整个 data 目录」，不留给用户手动翻目录。

### 实现
- 包内新增 `bin/admin.mjs`，`package.json` 加 `bin: { "dsh-shiori-admin": "./bin/admin.mjs" }`。
- 子命令：
  - `dsh-shiori-admin destroy --data <path>`：二次确认（要求输入 data 路径原文），先列出将删的文件数，再递归删除整个 dataRoot。
  - `dsh-shiori-admin destroy --yes`：跳过确认（给脚本用）。
  - `dsh-shiori-admin status`：只读，打印 data/state 路径、大小、topic 数。
- 面板侧同步加一个「卸载并清除数据」按钮（危险色 + 二次确认），走同一套实现。
- **不删除** stateRoot 以外的任何东西；不碰 DSH 配置；不自动执行 `dsh plugin remove`（提示用户手动跑，避免插件自己删自己）。

### 验收
- 跑命令后 dataRoot 整个消失，stateRoot 保留
- 没给 `--yes` 时不输入路径就退出
- 面板按钮与命令行为一致

## S7 闪回图谱方案 B（P2）

### 目标
两级聚类：第 1 层只画簇圆（簇 = 组，或按 embedding 聚的类），点开进簇内再画连线。
依赖 S3 的分组先落地。

### 改动
- `client/index.js` 图谱渲染拆成两级视图 + 面包屑（全部 / 某簇 / 返回）
- 数据侧新增 `getGraph({ level, cluster })`：level=1 返回簇与计数，level=2 返回簇内节点与边
- 保留现有 `getGraph` 全量返回作为兼容路径

### 验收
- 30 张卡的图谱首屏不再是一团线，簇圆可点开
- 空簇不渲染；单卡簇降级为点
